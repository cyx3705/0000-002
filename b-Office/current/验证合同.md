# HistoryExemplum 验证合同

## 验证原则

- 每项现行需求必须对应至少一种可重复的验收方式。
- 命令的权威声明位于根目录 project.manifest.json。
- 未执行、失败和不适用必须明确区分。

## 验证层级

| 编号 | 层级 | 适用时机 | 命令或步骤 | 通过标准 |
| --- | --- | --- | --- | --- |
| VERIFY-FAST | 快速检查 | 每次相关修改后 | `dotnet build .\b-Code\HistoryExemplum\HistoryExemplum.csproj -c Release` | 0 警告、0 错误 |
| VERIFY-UNIT | 自动验证 | 指令、页面修改后 | `dotnet run --project .\b-Code\HistoryExemplum.Tests\HistoryExemplum.Tests.csproj -c Release` | 全部 PASS：指令注册与隐藏标记、owner 由域推出、按钮/动作/指令/取数对得上、版本一致、宿主装载冒烟；{{业务用例}} |
| VERIFY-FULL | 完整回归 | 里程碑收口前 | `powershell -File .\b-Code\Test-ProjectContract.ps1 -Instantiation` | 版本三处一致、模块身份、页面 owner、BOM、`z-Publish/** binary`、链接与密钥检查全部通过 |
| VERIFY-PACK | 发布候选 | 出包前 | `vulcan.dev.submit`（或本地 `eng\Build-HistoryExemplumPackage.ps1`） | 候选含 manifest、DLL、XML、docs 与无 BOM 的 SHA256SUMS |
| VERIFY-ACCEPT | 装入宿主 | submit 热装后 | `vulcan.module.list`；Aurora 场景列表 | 模块 attached、指令数与离线一致；场景 HistoryExemplum 与页面存在 |
